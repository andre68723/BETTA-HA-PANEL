# Tools

Internal checks, generators and shared Python modules live here, including shell helpers used by the check runner. Direct build, check, device and local-editor
entry points live in [scripts/](../scripts/README.md). Run generator commands from the repository root.

| Script | Invoked | What it does |
| --- | --- | --- |
| `test_host.sh` | Called by `check.sh` for `panel4` and `paneljc` | Supports all five variants; the check runner selects panel4 and paneljc. Local policy and parser tests inject failures; fixed calendar fixtures retain real worker deadlines. Needs fetched cJSON or system `libcjson` development files, no device or SDK build. |
| `editor_local.py` | Called by `scripts/editor_local.sh`; tooling tests | Implements the local editor server, synthetic API and local saves. |
| `apply_component_patches.py` | **Automatic** -- the root `CMakeLists.txt` runs it on every configure, right after `project()` | Re-applies the small edits fetched components need (esp_hosted SDIO workaround, panel4/panel10 BSP fixes under IDF 6) after the component manager overwrites `managed_components/`. `--check` reports without changing files. |
| `generate_component_versions.py` | **Automatic** -- `main/CMakeLists.txt` runs it at configure time | Turns `dependencies.lock`'s resolved versions into a C header, so `GET /api/version` reports what was actually fetched, not just what the manifest asked for. |
| `check_web.py` | Called by `check.sh` | HTML/translation/Markdown-link checks, plus a temporary build, fingerprint, syntax and gzip check of the firmware-only WebUI assets. |
| `check_source_sizes.py` | Called by `check.sh` | Checks source limits, or documentation with `--docs` (warn above 250, fail above 300, preserving generated-page exemptions and frozen release-note ceilings). Source mode warns above 800 lines and fails above 2,999 for handwritten project sources. A few existing larger files have frozen individual ceilings (`LEGACY_CEILINGS` in the script) pending proper refactors; generated fonts, vendored touch code and Git-ignored build files are excluded. |
| `check_component_updates.py` | Manual, "before touching `dependencies.lock*` or the manifests" ([docs/development/components.md](../docs/development/components.md)) | Compares every managed component's locked version and manifest constraint against the newest version on the Espressif component registry (and shows the newest patch of the locked major.minor line as "Same line"; `esp_hosted` is only compared within its v2 major, `TRACK_MAJOR` in the script) (network access; kept outside build-time hooks so offline builds still work). |
| `capture_device_pages.py` | Manual | Captures every page of a panel's layout as PNG plus `manifest.json` (firmware commit, layout and reference hashes); never overwrites a set. |
| `import_device_captures.py` | Manual, after a visible change | `--board panel4|paneljc`: replaces `docs/img/<board>/` with a capture set and rewrites `docs/gallery-<board>.md`. |
| `style_diff.py` | Manual, before adding or retiring an appearance style | Renders the simulator fixtures in every style and prints how many widget pixels differ per style pair (median, mean, lowest pages). A review aid; `--min PCT` turns it into a gate. |
| `gallery_freshness.py` | Part of `scripts/check.sh`; imported by the gallery generator | Warns when files that influence rendering changed since the gallery was last generated (`--strict` fails). Stamp: `docs/img/gallery/sources.json`, refreshed by `generate_simulator_gallery.py` (`--stamp-only` without rendering). |
| `test_layouts.py` | `test_pages.sh`; `check.sh` calls `check` | Packs and validates the shared widget cases; renders topic pages; explicit device `load`/`restore`/`status` subcommands retain backup and graph-history guards. |
| `widget_cases.py`, `test_layout_cases.json`, `test_layout_entities_demo.json` | Imported by the gallery and test-page tools | Shared cases, role substitution and synthetic state helpers. `gallery` tags select previews; `gallery_only` entries are excluded from packs and their generated state/edge cases. `gallery_caps` keeps repeated gallery descriptions in one place. |
| `gallery_content.py` | Imported by the gallery and guide generators | Projects gallery-tagged cases into stable tiles and writes the gallery Markdown. The widget definitions live in `test_layout_cases.json`. |
| `editor_local_demo.py`, `editor_local/` | `editor_local.py`; tooling tests | Synthetic Inspector demo layout and optional local editor adapters. |
| `generate_simulator_gallery.py` | Manual, after a widget's look changes | Renders every widget and special-page image of [the gallery](../docs/gallery.md) with the SDL simulator (stable names per tile, stale images pruned, source stamp written) and rewrites `gallery.md`, without a device. `--stamp-only` refreshes the stamp without rendering. |
| `generate_widget_docs.py` | After widget metadata or gallery paths change | Writes the individual [widget guides](../docs/widgets/README.md) from `widget_docs_content.py`, public gallery metadata, committed previews and the firmware's size/domain table; no device or rendering. |
| `generate_check_diagram.py` | After `check.sh` gains or loses a check | Draws `docs/img/development/checks.svg`, the diagram in [Checks and device tests](../docs/development/testing.md). |
| `generate_docs_examples.py` | Manual, when refreshing README/editor examples | Uses public gallery data to render complete dashboard examples and capture the current web editor against a local read-only demo API. Run with `uv run --locked --group screenshots python tools/generate_docs_examples.py`; see [documentation maintenance](../docs/documentation.md). |
| `check_widget_layout.py` | `check.sh` (when cmake and SDL2 are installed), CI, gallery generation | Renders the gallery widgets, Matte comparison and size edge cases in the SDL simulator (panel4, `--variant paneljc` and `--variant tab5` geometry) in all four styles and fails on overlapping text, text on buttons or half on a panel, and content outside its tile; see [docs/development/testing.md](../docs/development/testing.md). |
| `generate_gallery.py` | Manual, optional | `<panel-ip>`: screenshots every widget and page on a real panel4 against real Home Assistant entities (`gallery_entities.json`, gitignored, copy the `.example.json`), to compare with the simulator gallery; shares `gallery_content.py` with the simulator gallery. See [docs/development/testing.md](../docs/development/testing.md#gallery). |
| `check_readability.py` | Called by `check_widget_layout.py`; `--strict <dump.jsonl>` by hand | Checks the simulator's semantic text dump for clipping and capital height below the 16 arcminute reference (panel4 role sizes). See [docs/development/testing.md](../docs/development/testing.md#semantic-readability-checks). |
| `calibrate_text_caps.py` | Manual, after a layout or widget change that affects text growth | `--write` regenerates the per-tile text size caps in `main/ui/text_scale.c` from the simulator fixtures (`tab5` for Panel4 and Tab5, `--variant paneljc` for the 10-inch boards). See [Code conventions](../docs/development/conventions.md#text-and-fonts). |
| `compare_editor_previews.py` | Manual, when a tile preview in the editor changes | Renders every editor tile preview next to the LVGL image of the same widget (also edge-case sizes with `--cases`, whole pages with `--pages`) under `/private/tmp/betta-editor-preview-*`, or the explicit `--output` directory. A review aid, not a gate. See [Web editor source](../docs/editor-source.md#layout-preview). |
| `vendor_cam_sensor.py` | Manual, when `esp_cam_sensor` moves to another registry version | `<version>`: re-vendors `components/esp_cam_sensor`, keeping the OV02C10 and Tab5 sensor drivers and our `project_include.cmake`. See [Components and patches](../docs/development/components.md#vendored-camera-component-and-the-p4-silicon-cap). |
| `ui_styles.py` | Imported by the gallery and layout tools | The appearance style IDs, default and fallback, matching `main/ui/theme/ui_style_registry.c`; `check_web.py` compares them. |
| `generate_notification_emoji.py` | Manual, when `main/ui/fonts/notification_emoji.txt` or the pinned Noto revision changes; `--check` verifies the committed table | Scales the popup's color emoji from the pinned Noto Emoji images to RGB565A8 and writes `notification_emoji_data.c` (needs Pillow and network, or a cache) |
| `generate_widget_fonts.py` | Manual, when a font source or character range changes; `--check` runs in `check.sh` | Cuts the three committed subsets the firmware renders at run time with `lv_tiny_ttf` (Poppins Medium text, Material Design Icons, Noto Emoji) into TrueType files and C arrays (`--poppins`, `--mdi`, `--emoji`, `--emoji-manifest`), embeds the Poppins subset in the editor stylesheet (`--web`) and checks that subsets, arrays and manifests agree (`--check`). See [the font policy](../main/ui/fonts/README.md). |
| `stress_test.py` | Manual | Rapid page navigation, repeated Room/House-import-style entity-discovery calls and bounded concurrent web-editor asset loads. `--webui-copies 2 --webui-concurrency 8` simulates two simultaneous opens of the bundled editor. Reports memory before/during/after and exits nonzero if any request fails, including duplicate asset requests (see docs/development/testing.md, "Memory/stability stress test"). |
| `lfs_repack.py` | Manual, after a partition table change that moves or resizes `storage` | `<old dump> <new size> <out image>`: copies every file of a LittleFS partition dump into a new image of the new size (needs `pip install littlefs-python`). Writes no device, see [docs/development/build.md](../docs/development/build.md#changing-the-partition-table). |
