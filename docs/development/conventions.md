# Code conventions

## Text and fonts

- Every text, symbol, icon and emoji is an `lv_tiny_ttf` font made at run time by `main/ui/text_font.c` from four
  committed subsets in `main/ui/fonts/`: Poppins **Medium** (default text), Poppins **Bold**
  (notification emphasis), Material Design Icons, Noto Emoji (monochrome). No bitmap fonts, no `lv_font_conv`;
  `tools/generate_widget_fonts.py` subsets the sources (see `main/ui/fonts/README.md`). The subsets cover Basic Latin,
  Latin-1, Euro and common punctuation; add a missing character to the range and regenerate. LVGL's Montserrat fonts are
  not compiled in; `LV_FONT_DEFAULT` is the tiny built-in unscii 8.
- **Roles, not pixels.** Ask for a role (`ui_font_role(UI_TEXT_LABEL)`, `ui_text_set(label, role, essential)`,
  `ui/theme/ui_typography.h`), never a size. The size is a pure, host-tested function (`ui/text_scale.c`) of the role,
  the board profile (Panel4 is the reference density, Tab5 one step up, 10-inch boards the Panel4 sizes with a 16 px
  floor) and the user's text step (0 Standard, 1 Larger, 2 Largest). Steps: 16, 20, 24, 28, 32, 36, 42, 48, 56, 64 px. A
  new board is a profile entry, not a change at call sites.
- **Metrics.** `lv_tiny_ttf` takes line height and base line from the font; the manager overrides them from a table in
  `text_scale.c` (base line = table value − 1). Do not use a size or icon font without a table row; check it against a
  screenshot.
- **Layout.** Lay out from `lv_font_get_line_height()`, not fixed offsets. Keep one-line labels in dot mode with a fixed
  one-line height and fit text with `ui_text_fit()` (2 px steps down to the board floor). Panel4 and Tab5 use the
  adaptive branches (`UI_TEXT_ADAPTIVE`), 10-inch boards fixed rows. A tile too small for larger text keeps a smaller
  one via `text_scale_tile_cap(board, type, w, h)`, a table generated by `tools/calibrate_text_caps.py` from the
  fixtures (`tests/simulator/layout_cases.json`, the gallery, readability and room fixtures). Add a fixture case when a
  size needs protection, then calibrate again. The energy page has its own cap row (growth only on screens of 1000 px
  or more).
- **Checks.** `tools/check_widget_layout.py` renders every variant, and with `--text-step 1|2` the larger steps; Panel4,
  Tab5 and paneljc must stay clean at all three. The simulator accepts `--text-step N` and `--text-cap N`.
- **Symbols and emoji.** Symbols are `APP_SYMBOL_*` with `APP_FONT_SYMBOL_SMALL/MEDIUM/LARGE`
  (`main/ui/fonts/app_symbols.h`), never `LV_SYMBOL_*`; tile icons come from `mdi_font_registry.h`. Notification text
  keeps supported emoji and shows `[Emoji]` for the rest (`ui/notification_text.c`, host-tested; set in
  `main/ui/fonts/emoji_codepoints.txt`). Do not embed brand logos.
- **Strings.** New UI strings go through `ui_i18n_get("key", "English fallback")` with entries in both built-in tables
  (`main/settings/i18n_store.c`). German uses real umlauts and `ß`; the English table stays ASCII apart from `°`
  (`tools/check_web.py` enforces both). A panel set to a dropped language shows English.

## Look and feel

- Buttons and bars use `main/ui/theme/ui_style.h` (`ui_style_button()`/`_auto()`, inset tracks, gauge arcs), not flat
  fills. The style (flat, glow, glass, matte; `ui_style_get()`) is independent of the theme colours. Keep a depth-free
  fallback behind `ui_style_has_depth()` (glow and glass) and use `ui_style_is_glass()`/`ui_style_is_glow()` where they
  differ. Prefer `switch (ui_style_get())` over if/else chains, so `-Wswitch` catches a forgotten style. IDs, default and
  the Flat fallback are in `ui_style_registry.c`
  ([appearance reference](../appearance-implementation.md#style-ids-and-compatibility)).
- Cards inside tiles (weather days) are rounded surfaces slightly lighter than the tile, label muted, value in the
  primary colour.

## New widget types

Touch: a row in `main/layout/widget_types.c` (size limits per variant, entity domains), `layout_validate.c`
(type-specific fields), `ui_widget_factory.c` (create/apply/unavailable), `main/CMakeLists.txt`,
`main/ha/ha_layout_entities.c` (subscribed entities come from the layout JSON; arrays such as `room_entities` need
reading), the editor and the docs. Template: `w_contact.c` or `w_room.c`. Also add a `GROUPS` entry in
`tools/generate_widget_docs.py` and a card in the feature tour.

If the domain's real `attributes` can exceed about 1 KB (forecast, preset or mode arrays, map or room data), it needs a
compact serializer in `main/ha/ha_attr_serialize.c` (`ha_client_serialize_<domain>_attrs_compact`; keep only the fields
the widget reads, inventory them, do not guess; see the weather, light, climate, cover and fan ones). Without one, an
overflow degrades to a valid JSON with only `device_class`, `unit_of_measurement`, `friendly_name` and `entity_picture`
(`ha_attrs_build_generic_overflow_fallback()`), and the widget loses everything else above about 1.28 KB. Serializers
were added reactively, which is why binary_sensor, cover, fan, camera, vacuum and generic `sensor.` went unnoticed.

## Web editor

- Edit the plain files in `components/webui/www/` (`index.html`, `styles.css`, `css/*.css`, `js/*.js`; files and adding
  one: [Web editor source](../editor-source.md)); they are gzipped at build time. `tools/check.sh` checks the JavaScript.
- New texts need keys in the `en` and `de` tables of `WEB_I18N_BUILTIN` in `js/i18n.js`. A new widget type also goes into
  `ENTITY_PICKER_CONFIGS`, the Add menu, the size tables and `tilePreviewMarkup` (`js/tile-previews.js`).
- **Without flashing:** serve `components/webui/www` on localhost and proxy `/api` to a panel, then reload instead of
  flashing for every CSS or JS change. The editor saves to the panel it talks to; make the proxy read-only when you only
  want to look. The panel serves its own gzip-embedded copy, so on-disk edits change nothing on a device until rebuilt.
  Send `Cache-Control: no-store` for everything outside `/api/*`, or use a new port: a browser can keep serving a cached
  file for the whole session, even in a new tab.
- **Browser tests:** use the Safari MCP at 90 % zoom. Reading page state (`get_page_content`, `evaluate_javascript`) is
  cheaper than a screenshot; screenshot only when the rendering itself is the subject. CSS zoom does not scale `vh`, so
  judge heights without zoom.

## Data compatibility

The supported upgrade path is from upstream v0.8.2 (`420df764`). Whatever it stored must keep working:
`/littlefs/layout.json` and `/littlefs/settings.json` (nested `wifi`/`ha`/`time`/`ui`), the NVS namespace `runtime_sec`
with `wifi_pwd`/`ha_token`, and the type name `roborock_tile` (renamed `vacuum_tile` on load). Older formats and the
fork's unpublished intermediate formats get no migration; check `git show 420df764:<path>` before adding or removing
one. The editor is served by the firmware, so it never handles an older firmware's API.

## Build rules

- Warnings are errors (`-Werror`, GCC 15); some only appear with `-Os`.
- LVGL calls only from the UI task or with the display lock held; esp_wifi calls go through the mutex in `wifi_mgr.c`.
- **Flash budget:** the app slot is 5 MB with about 7 % free (local v0.9.0 paneljc build, easter egg off). See
  [Flash budget](../hardware/storage.md#flash-budget-paneljc) before adding fonts, images or libraries.
  `CONFIG_COMPILER_OPTIMIZATION_SIZE=y` would free about 340 KB but is **not enabled** (not regression-tested, harder
  debugging); decide on it before removing features.
